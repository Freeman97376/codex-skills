# 两层验收与费用边界

## 确定性场景

每个场景先写输入、操作、预期、隐私边界、可观察证据及清理步骤。使用合成账号/材料，经真实公网前缀完成登录、静态资源/API/跳转、受保护材料读取、建立初稿、保存、刷新和重新打开。另一账号须不能越权读写。验证实际加密存储与权限，页面未展示明文不是加密证据。

受保护材料的原文是否允许进入引用、发送给模型、进入生成稿或被人工接受，分别依据已确认合同断言。不得期待企业原文无条件出现在初稿。合成资料不免除隐私合同；真实用户资料不因测试请求就允许外发。

确定性测试可用受控替身，但不得将替身结果报告为真实模型成功。真实材料测试分别列出：原件完整性、可解析性、业务预期、端到端和人工判断；每项说明实际覆盖及未覆盖部分。

预生产先验证同等路径和主要负向场景；生产只执行已批准、可清理、不会破坏真实业务的合成操作。不能把“测试失败规则”理解为允许在生产注入破坏性故障。

## DeepSeek 实际链路

项目配置填写准确业务模型、当前价格来源与核对时间、计费单位、输入/输出最大量、自动重试及内部调用次数。从应用实际调用路径观察用量，不能只数顶层 HTTP 请求。外部服务 stub、离线安装与认证预检均不算真实验收。

至少验证合同要求的调用、结果接收、保存及人工接受边界。需要人工判断质量时保留待验收，不能由模型自行宣布人工通过。与本次发布无关的场景可说明不适用；不得为节省预算省略必需链路后宣布通过。

## 每次发布总额最多 50 元

本技能提供计费控制规范，不包含可强制限制供应商计费的执行器。执行代理必须先确认项目实际计费/限额能力，不能声称文档本身实现硬限额。

1. 本次预算授权适用后，DeepSeek 业务测试在累计人民币 50 元内无需逐次确认。CC 模型用量另行确认；有更低项目上限时采用较低者。不能自动提高上限。
2. 为本次发布建立统一持久台账，串行调用为默认；并发仅在具备原子预留及对账能力时使用。修复、重试、进程重启和恢复同一次发布都复用该台账，禁止另建发布编号逃避额度。
3. 调用前计算保守最大费用，包含输入、输出上限、可计费推理项、最坏缓存计价、内部调用和 SDK/代理自动重试。依据当前官方计价或可核实账单；外币计价须记录保守换算及费用缓冲。不凭记忆填费率。
4. `已结算费用 + 未结算预留 + 本次最大费用 <= 50 元` 才能发起。通过输出/重试/内部调用上限使预留可界定；不能界定或计费不透明就阻塞付费场景，继续其他可执行检查。
5. 每次调用预先记录请求标识、用途与预留，返回后记录可核实用量、费用、来源、结果及剩余额度。费用计算使用精确小数或最小货币单位并向上取保守值，避免浮点低估。
6. 超时、取消、网络中断或账单延迟不代表免费。未对账调用保留全部预留；只有可靠结算证据才能释放余额。应用隐藏调用或重试无法纳入预算时先修复可观测性，不盲目重复。
7. 达到验收条件就停止，不以花完预算为目标。额度不足仍有必需场景则记“验收阻塞”，保留已有结果；不追加预算、不切换供应商或把未测改为通过。

## 清理与恢复

创建测试资源前记录其发布编号、所有者、隔离命名和删除/撤销方式。无论成功失败都执行 finally/补偿清理，并核实账号、会话、材料、临时凭证；重启后依据台账继续，不能只依赖单个进程的 finally。证据脱敏后保留，清理范围不包含真实用户资源。

若后续业务失败或预算不足发生在部署后，使用已批准的失败预案，而不是让未通过版本自动停留或擅自恢复数据库。业务失败、清理失败与恢复结果分别记录。
