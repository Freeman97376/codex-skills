# 双入口项目记录

## 目标与授权

人通过 `office/records/README.md` 理解项目、进展和待决事项；Agent 通过
`office/records/agent-index.md` 定位模块、有效约定、证据与接续状态。
两个入口必须引用同一份事实来源。入口不是第二套权限政策，历史授权也不
构成当前操作许可。只读任务不写记录；授权维护时仅更新受影响的文档。

## 文件职责

| 相对 records/ 的位置 | 职责 | 更新策略 |
| --- | --- | --- |
| README.md | 人的阅读导航、简短有来源的摘要 | 当前视图，不复制完整证据 |
| agent-index.md | 按任务读取的路径、核验和接续规则 | 导航，不重新定义治理权限 |
| overview.md | 目标、用户、范围、术语和非目标 | 更新当前事实，关联重要改动 |
| current-state.md | 本地/远端/部署基线、实现状态、风险、待决事项 | 不混用不同基线或过期测试 |
| architecture/overview.md | 模块与数据流地图 | 已有权威架构则只建导航，不复制重写 |
| architecture/modules/ | 复杂模块的按需明细 | 已有模块文档则链接复用，不强制建目录 |
| changes/ | 重要改动的原因、前后行为、影响和证据 | 追加；更正须标明替代关系 |
| decision-log.md | 既有决策及其索引 | 保留旧条目；复杂决策按需拆分并链接 |
| task-log.md | 既有任务历史及简短结果索引 | 不重复复制改动记录 |
| handoffs/ | 跨会话任务的目标、状态、阻塞、下一步 | 活跃时更新，完成后保留最终状态 |
| 既有测试台账/用例/错误 | 质量证据 | 由测试治理维护，本模块引用 |
| reports/ | 人类阶段报告 | 按需生成带截止时间的快照，非当前事实源 |

## 记录协议

当前事实、历史事件、任务接续采用不同生命周期，不强行统一状态。
重要记录有稳定编号、日期、模块/路径、依据版本、关联记录、验证范围和
替代关系。面向人的摘要在前，技术定位与证据在后。unknown / 未核验是
合法状态，不能为了填模板而制造事实或写成 passed。

- **当前事实**：区分代码核对、历史记录报告和计划。写明核对日期、分支、
  提交及是否存在未提交改动；重要未提交依据记录文件指纹。陈述对应的
  本地工作树、远端候选和部署环境必须分别标识。
- **历史事件**：原因、前后行为、影响、验证、遗留问题；更正追加新记录，
  使用 supersedes/superseded_by 或正文链接，不能无痕改写历史结论。
- **关键决策**：提议、已接受、已替代、撤销；接受必须有真实用户依据。
- **任务接续**：活跃、阻塞、完成、归档；保留目标、实际改动、下一步、
  已知授权边界和工作区状态。普通问答不生成接续文件。
- **验证**：实现状态与验证状态独立。引用旧测试时标为历史证据；关联代码
  或合同变化后依测试治理重新评估，未重跑不得称当前通过。

## 更新步骤

1. 先读项目治理、Agent 入口和当前状态，按任务定位已有权威文档与活跃接续；不批量读取全库。维护入口时再核对人的首页。
2. 检查当前代码、相关差异和版本；只修改与本次授权相关的当前事实。
3. 对重要行为、架构、接口、权限、数据、部署或错误变化追加改动记录。
   新旧记录相互链接，任务日志只保留简短索引；不把每次命令都记成事件。
4. 若改变未来约定，追加决策；若需跨会话继续，更新接续状态。
5. 仅当导航或摘要受影响时更新入口，确保两者指向同一事实；不为留痕而改写两份首页。
6. 检查链接、编号、基线、实现/验证区分和隐私。报告实际验证与未验证项。

## 项目启动与收尾合同

维护已有项目时，把以下义务合并进该项目的 `office/AGENTS.md`，根 `AGENTS.md`
保留发现和委托路径。更新 Skill 源或模板不代表已有项目已接入；须核对项目
本地 Skill、引用文件和实际启动/收尾条款，保留更严格规则及测试目录。

**启动**：新任务开展实质性工作前，以及跨会话或上下文恢复后，先读 Agent
入口和当前状态，核对实际根、分支、提交和工作区差异。再读任务相关架构、
有效决策、未解决错误与活跃接续。任务内基线或规则改变时重新核对，不要求
每个小步骤重复通读。缺文件或冲突先报告；只读时不自动修复或追加日志。

**收尾**：授权改动完成后，以实际差异和本轮验证逐项判断记录影响：

| 变化 | 维护位置 |
| --- | --- |
| 功能、范围、进度或风险 | 对应当前事实；重要变化追加 changes 或复用既有专题 |
| 职责、依赖、接口或数据流 | 既有权威架构/合同；架构导航仅在路径或摘要改变时更新 |
| 影响未来行为的已接受取舍 | 决策记录，标明与旧决定的替代关系和真实用户依据 |
| 测试证据或错误状态 | 按既有测试治理处理，不凭文档检查更新 passed/verified |
| 跨会话未完事项或已完成接续 | 更新相关 handoff；完成后保留最终状态，不重开旧任务 |
| 纯问答、只读检查、无事实影响的小改动 | 无需生成记录；重要差异在回复中说明 |

先更新受影响的权威事实，再决定入口摘要是否需要变动。收尾回复列出已更新
记录；无需更新时说明原因；延后项说明原因、影响和下一步。存在相关过时事实
时不能宣称同步完成。只读或执行限制优先，不能用治理流程扩大授权。

**阅读层级**：人的首页保持目标、功能、进展、风险和待决事项；Agent 入口
保持简短定位。代码明细留在按需证据中，优先路径、函数和版本，只有关键业务、
权限、隐私、删除/迁移或争议行为需要人工判断时才展示短片段并解释影响。

**验证边界**：核对链接、源版本及“差异—受影响记录”的对应关系。结构检查
只能证明结构；人工或 Agent 的语义复核仍必要。不增加只匹配政策措辞的测试，
不把规则写入等同于后台自动同步、强制执行或未来 Agent 已遵守。

## 读取与失效

Agent 先读入口，再读相关架构、有效决策、未解决错误和活跃接续。需要原因
时再追历史。源代码与文档冲突时报告冲突并核查，不把代码缺陷自动当成新
业务合同。历史摘要、模型记忆和检索结果均需回到原始证据核验。

## 兼容、隐私与自动化边界

保留旧日志、测试结构和架构文档。先建立导航与来源映射，不批量重写旧
内容或迁移大附件。项目秘密、完整聊天、无关个人资料和重复原始日志不
进入记录；证据链接可能失效，失效时标记，不编造替代证据。阶段报告及
审阅副本注明生成时间、来源和不可单独维护的快照属性。

本模块提供规则与模板，不承诺自动记忆、自动同步或后台监控。不得自动
确认决策、关闭错误、宣称测试通过、删除历史、启动付费检索或安装服务。
先通过人工维护与按需读取工作流，后续自动化需另行设计和授权。
