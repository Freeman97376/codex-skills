# 上线检查与发布验收

将每次发布推进到有证据的结论。通用规则在本技能，真实路径、服务身份、CI 和业务合同在目标项目。Mantle 是首个计划验证项目，不代表已经完成验证。

## 先确定任务模式与现场

1. 解析目标项目真实根目录，读取其 AGENTS.md、office/README.md、office/AGENTS.md 和工作区状态。遵守该项目的治理引导要求；保护用户未提交工作。当前技能库不是默认被发布项目。已采用共用记录的项目还须先读 Agent 入口、当前状态和相关活跃交接；它们只提供线索，不替代现场版本、CI 与运行证据。
2. 区分“制定流程/只读审查”和“执行发布检查”。前者只准备流程或报告，不修复产品、付费调用或部署。后者按用户授权自动完成范围内检查、修复与回归；不擅自扩大交付或改变验收合同。
3. 仅在文件写入已获授权时，使用 [项目配置模板](assets/project-profile.md) 在目标项目建立或复用 `office/releases/project-profile.md`；为本次发布创建 `office/records/releases/<release-id>/release.md`，使用 [发布记录模板](assets/release-record.md)。真实配置必须现场核实，未知项不能填为通过。恢复中断运行时复用发布编号、失败历史及费用台账，禁止清零重来。纯只读审查在回复中列出差异及建议，不因模板存在而创建发布单或改项目状态。
4. 明确核心业务、隐私预期、必需 CI、风险等级、证据依赖和恢复方案。只询问阻碍下一步的缺项；现有授权与已确认偏好继续有效。

## 授权与默认值

- 用户选定的默认流程：自动检查与修复；Codex＋Claude 独立审查；部署前用户确认；技术验收通过后可以运行，人工验收单独记录。
- 真实业务模型测试默认 DeepSeek API，每次发布累计上限人民币 50 元，含实际计费失败与重试。明确执行本流程且该预算授权适用于本次任务时，限额内无需逐次询问。自动匹配技能、阅读或制作流程本身不授权付费调用。
- CC 使用单独的已确认模型/推理级别/角色/渠道/轮次配置，不能借用 DeepSeek 的 50 元授权。运行前阅读 [CC 调用流程](references/cc-review.md)。不硬编码模型或凭证，不临时追加计费。
- 部署确认必须针对已经准备完整的候选版本与失败预案。授权后按原范围连续执行部署、业务验收与清理；候选提交、产物、配置、迁移或恢复预案发生实质变化时重新提交对应变更供确认。
- 兼容的纯应用回退仅在具体预案已批准时自动执行。数据库恢复、数据重写恢复或兼容性不明时停止并等待用户确认。不得自动降库。

## 执行关卡

读取 [关卡与失败规则](references/gates.md)，依次执行：

范围与合同 → 测试环境预检 → 影响分析与定向回归 → CC 独立审查 → 锁定候选版本及必需 CI → 生产环境预检 → 备份与部署确认 → 部署指定版本 → 公网两层验收与清理 → 交付。

- 行为修复按目标项目的 change-test 治理处理；回归测试在产品原生测试目录，正式验收合同的变更需按项目要求确认。
- 前置条件不足记为阻塞，测试失败记为失败；不能把测试工具失败等同产品失败，也不能视为通过。必需 CI 取消、跳过、缺失、仍运行均不能放行，除非已确认合同明确说明该项不适用。
- CC 审查缺失或受阻时，继续独立可完成的检查，保留部署阻断；不以自审替代用户选定的独立审查。
- 真实模型调用前读取 [验收与预算](references/acceptance-budget.md)。健康接口成功不能代替业务验收。
- 有修复则重新分析影响、使相关证据失效、运行测试与必要复审；新候选版本必须等待自己的必需 CI。不得删除有效断言、放宽隐私要求或用旧测试总数掩盖未测范围。

## 证据与最终输出

每份证据绑定发布编号、候选提交/产物指纹、相关文件指纹、测试/夹具版本、环境与配置标识、时间、命令或操作、预期、实际结果和脱敏证据位置。非 Git 项目使用可复核的源码/产物清单，不能捏造提交号。

结果用：通过、失败、阻塞、未执行、失效、不适用（附理由）。相关代码、合同、测试、配置或环境变化后，旧证据失效；复用其他证据须记录依赖不变的依据和范围。保留失败，再追加恢复结果。

交付分别列出：代码已提交、必需 CI、独立审查、实际生产版本、确定性验收、真实模型验收与费用、清理、人工验收、已知限制、备份与恢复验证范围。人工待验收不能写为已通过；恢复旧版成功不能写为候选版本发布成功。

先在目标项目验证生产预检、版本与 CI 绑定、两层公网验收、清理及恢复，再把可靠步骤接入 CD。文档、离线校验和本地模拟不证明真实 CC、预算计费或生产部署已通过。


## 与项目共用记录衔接

发布单是本次候选、关卡、费用、失败及恢复证据的权威来源。授权执行结束或中断交接时，先更新发布单，再将影响项目完成判断、风险和阻塞的结论写入既有当前状态，并链接发布编号/证据；不要在两个入口复制关卡与费用台账。

本地实现、候选提交/CI、实际部署版本、业务验收和人工验收分别记录。历史验收或文档检查不能证明线上当前状态；若部署后无法核实实际版本，写“待核实”而非继续显示候选已部署。恢复成功保留候选失败结论。CI 被关闭也不自动满足必需 CI 合同。

收尾说明记录已更新、无需更新的原因及延后项的影响/下一步；未完成工作使用原有交接，不自动重新发起发布。仅在导航或摘要改变时维护人的首页和 Agent 入口。只读任务只报告差异；记录要求不扩展付费、部署、恢复或独立审查授权。
