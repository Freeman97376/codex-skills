# 发布关卡与失败处置

## 关卡表

| 关卡 | 工作与通过条件 | 失败出口 |
| --- | --- | --- |
| 0 范围与合同 | 明确交付/延期/限制/阻断项；每个场景有输入、操作、预期和证据。材料引用、模型生成、人工接受分别定义。确认非核心风险的接受机制。 | 合同不清则该场景阻塞，不能随结果调整预期。 |
| 1 测试环境预检 | 核实解释器、依赖、夹具、临时目录、服务/测试身份、Git 元数据读取依赖及清理能力。验证测试不误操作真实业务数据。 | 记录工具或环境故障，修复后重跑，不能直接判产品失败。 |
| 2 影响分析与回归 | 搜索产品、前端测试、后端合同测试、配置与迁移；建立改动→合同→测试→环境映射。运行定向回归并同步过期断言。 | 范围内修复后重测；更改正式合同需相应确认。 |
| 3 CC 独立审查 | 按 cc-review.md 实际执行，审查代码/权限/隐私/完整性/迁移/恢复。核实每项发现及代码范围。审查与候选内容可追溯。 | 修复并复审；没有真实审查证据不能标为完成。 |
| 4 候选版本与 CI | 锁定完整提交号、产物指纹和构建来源。使用项目已确认的必需 CI 清单，核对结果实际针对该提交（含合并提交/构建提交差异）。 | 必需项失败、缺失、跳过、取消、未完成则阻塞。不能自创缩减的必需清单。 |
| 5 生产预检 | 核实入口前缀、反代、实际服务身份/组/目录/运行约束、系统与服务管理器版本、磁盘、数据库版本、配置警告和实际生效结果。以服务身份验证代码导入、依赖与必要文件读取；密钥只验证可用性，不输出值。代码可读不应导致配置/密钥/上传/备份权限放宽。 | 修复环境并重测受影响项；配置文件存在不等于进程已使用。 |
| 6 备份与放行 | 记录应用/数据/配置/必要密钥恢复依赖、备份时间/位置/完整性、恢复点与可接受数据损失；涉及迁移按风险做隔离恢复验证。提交当前候选、CI/审查/测试证据、限制、部署与恢复预案及剩余预算供用户确认。 | 无可执行恢复方案不部署。归档完整性不能冒充恢复验证；不伪造审批。 |
| 7 指定版本部署 | 使用已批准提交或产物；记录配置/迁移变化并核对实际运行版本。不从浮动分支拉取未受检版本。 | 保存失败证据并执行已批准处置，不继续扩大变更。 |
| 8 公网验收与清理 | 经真实入口完成 acceptance-budget.md 的两层验收、跨账号隔离和存储检查。无论成功失败都尝试清理，并独立验证结果。 | 业务或清理失败单独记录；核心失败则候选验收失败。 |
| 9 交付 | 记录各状态、生产版本、证据链接、审查覆盖/遗漏、费用、限制、备份和人工步骤。技术通过可运行，人工状态单列。 | 不把未执行或历史证据写为本次通过。 |

预生产环境应重现生产访问前缀，覆盖登录、静态资源、API、写作、脱敏和跳转。直接应用入口、代理路径与公网入口分别取证，不能互相替代。浏览器保存后刷新/重新进入也是验证步骤，单个 API 200 不足以证明。

## 变更与证据失效

- 审查后变更重新做影响分析；相关代码需复审。只改提交元数据而文件内容不变时，可说明指纹等价的审查复用范围，但候选 CI 仍必须匹配实际提交。
- 绑定产品、测试、夹具、依赖/锁文件、构建、配置和环境依赖；不能只看产品文件是否变化。
- 部署准备之后发生变化，重跑相关关卡并更新发布单；新候选或实质恢复变化不沿用旧批准。
- 失败日志与恢复记录追加保存，不覆写历史。原始敏感日志留在适当受控位置，Office 只留必要脱敏摘要和定位信息。
- 隐私泄露、越权、数据损坏、迁移兼容性不明、必需 CI 未通过和核心业务失败不能豁免。其他限制由用户在知道影响/负责人/处理期限后明确接受，不能把它们改记“通过”。

## 部署后的处置决策

1. 保留脱敏失败证据，判断用户/数据影响，核对预案触发条件。
2. 纯应用回退且旧版与当前数据库/已产生的数据兼容：仅执行已批准的具体回退，然后重新验证生产版本及核心业务。
3. 有数据库迁移、数据重写、数据恢复或兼容性不明：停止后续变更，按预案隔离功能、保护现场，等待用户确认恢复动作。不能自动降库或启动不兼容旧版。
4. 隐私泄露或越权：按预案优先阻断受影响入口并立即报告。预案不能覆盖的操作先明确影响与所需授权。
5. 临时账户/会话/凭证清理采用预先定义的补偿步骤，只处理本轮拥有的测试资源；清理失败列出所有者与下一步，不能删除必要证据或宣告完全结束。
6. 分开记录候选版本失败、恢复执行结果和最终生产状态。恢复成功不改变候选版本失败的结论。
